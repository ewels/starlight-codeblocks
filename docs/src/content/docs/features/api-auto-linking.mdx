A code example uses names from libraries: modules, functions, classes and their methods. In a normal code block, a reader who wants the reference page of a name must search for it. API auto-linking finds these names and links them to their reference pages. You write nothing in the code block.

export const basic = `
\`\`\`py title="report.py"
import json
from pathlib import Path

run = json.loads(Path("run.json").read_text())
print(run["status"])
\`\`\`
`;

<Example code={basic} />

The Python adapter reads the two imports. It links `json`, `pathlib`, `json.loads`, `Path` and `read_text` to the Python documentation. It knows that `read_text` belongs to `Path`, because the code calls `Path` first. Hover over a link, or move keyboard focus to it, to see a card with the kind, the name, a short summary and the source.

## Syntax

API auto-linking has no syntax. It runs on every code block in a language that has an adapter.

| Syntax | Where | Effect |
|---|---|---|
| `apiLinks=false` | Code block fence line | Turns the feature off for one code block |
| `nextflow="config"` | Code block fence line | Links a Nextflow code block as a config file |

## Examples

### Nextflow

A Nextflow workflow gets links for the keywords, the channel factory, `params` and the process from nf-core:

export const nextflowExample = `
\`\`\`nextflow title="main.nf"
include { FASTQC } from './modules/nf-core/fastqc/main'

workflow {
    reads = channel.fromFilePairs(params.reads)
    FASTQC(reads)
}
\`\`\`
`;

### Nextflow config file

A code block with a title that ends in `.config` is a config file. It gets links for the config scopes, such as `params`, for the settings, such as `docker.enabled`, and for the directives in the `process` scope:

export const nextflowConfig = `
\`\`\`nextflow title="nextflow.config"
params {
    input = 'samples.csv'
}

docker.enabled = true

process {
    cpus = 2
    memory = '4 GB'
}
\`\`\`
`;

### An adapter for your own names

A site can link its own names with an adapter of its own. This site links the names that a block imports from starlight-codeblocks:

export const siteAdapter = `
\`\`\`js title="adapters.mjs"
import { nextflow } from 'starlight-codeblocks/adapters/nextflow';
import { python } from 'starlight-codeblocks/adapters/python';

export const adapters = [python(), nextflow()];
\`\`\`
`;

### Turn links off for one block

With `apiLinks=false`, the same Python block has no links:

export const off = `
\`\`\`py title="report.py" apiLinks=false
import json

run = json.loads(text)
\`\`\`
`;

## Behaviour

An adapter finds the names in a code block and resolves each one against its indexes. It links a name only when it is certain about the name. All other names stay plain text.

- Links:
  - A link has a dotted underline. On hover and on focus, the underline is solid and the link gets a faint background.
  - Names inside strings and comments never link.
- The card:
  - After 150 ms of hover, or at once on keyboard focus, a card opens under the link. It shows the signature, or the kind and the qualified name. Under that, it shows a summary, if the index has one, and the source of the link.
  - The source has the icon of its project, if [Simple Icons](https://simpleicons.org/) has one, such as Python, NumPy or Flask.
  - The card stays open while the mouse cursor is on the link or on the card. Press <kbd>Escape</kbd> to close it. The card closes when the link loses focus.
- Screen readers:
  - Screen readers get the text of the card as the description of the link.
- Copy:
  - The copied text is the same as the code. Links and cards are not part of it.
- Without JavaScript:
  - The links work, but there is no card.

Adapters load their indexes once for each build. An index that the build fetches from another site stays on disk in `node_modules/.cache/starlight-codeblocks/`, so later builds do not fetch it again. If a fetch fails and there is no copy on disk, the build logs a warning, and the names from that index stay plain text. The build does not fail.

## Options

<Options />

A list in `adapters` replaces the default list. To change one adapter, put all the adapters that you want in the list:

```js title="astro.config.mjs"
import codeblocks from 'starlight-codeblocks';
import { nextflow } from 'starlight-codeblocks/adapters/nextflow';
import { python } from 'starlight-codeblocks/adapters/python';

codeblocks({
  apiLinks: {
    adapters: [python({ inventories: ['https://numpy.org/doc/stable/objects.inv'] }), nextflow()],
  },
});
```

To add an adapter for another language or library, see [Write an API link adapter](/starlight-codeblocks/extend/write-an-api-link-adapter/).

## Python adapter

The Python adapter runs on `py`, `python` and `pycon` code blocks. It reads `import x`, `import x as y` and `from a import b as c` in the block. Then it links the names that those imports bind, and chains of attributes on them, such as `os.path.join`.

<Options adapter="python" />

An `objects.inv` file has no signatures and no summaries. For its names, the card shows the kind, the qualified name and the documentation that it comes from. The adapter also fetches the documentation page of each name when the site builds. It shows the first sentence of the description on the card, cut to 16 words. The page stays on disk with the inventories. If the page does not load, the card has no summary, and the build shows no warning.

If the site also uses starlight-pydocs, install both plugins. The Python adapter then links the names of every package that starlight-pydocs documents, with no configuration:

```js title="astro.config.mjs"
starlight({
  plugins: [starlightPydocs({ packages: [{ name: 'myproject' }] }), codeblocks()],
});
```

For these names, the card has the signature and the first sentence of the docstring, as starlight-pydocs shows them. A name links to the site's own page, also if an inventory has the same name. Names that a package re-exports, such as `myproject.Report` from a private `myproject._report` module, link to the object's page. If starlight-pydocs documents one package at two bases, such as the current version and an older one, the first entry in its `packages` list wins.

To link a block to another version, set `pydocsBase` to the `base` of that package. starlight-pydocs sets it on the examples in its docstrings, so that each version links to its own pages. You can also set it on a block that you write:

````md
```py pydocsBase="1x/api/myproject"
from myproject import Report
```
````

A name that the package at `pydocsBase` does not have links to the first package that has it, or to an inventory. If no package has the base, the build shows a warning, and the block links as it does without the attribute.

## Nextflow adapter

The Nextflow adapter runs on `nextflow` and `nf` code blocks. It reads the names from the [API index](#api-index-adapter) of the [Nextflow language server](https://github.com/nextflow-io/language-server). The index has the names, signatures and descriptions of the hover hints in VS Code, and a docs link for each name. The build fetches the index of the latest language server release once, and keeps it on disk. If the index does not load, the adapter links only the modules from the `modules` option.

The adapter links:

- The keywords that start a declaration, such as `process`, `workflow` and `include`.
- The section labels of processes and workflows, such as `input:`, `script:`, `take:` and `emit:`.
- Process directives at the start of a statement in a `process` body, such as `publishDir` and `cpus`.
- Input and output qualifiers, such as `val`, `path` and `tuple`, and output options, such as `emit:`. In a typed process, the stage directives and output functions, such as `stageAs` and `file()`.
- Channel factories, such as `channel.of` and `channel.fromPath`, and operators on a channel, such as `.map` and `.view`.
- Global names, such as `params`, `projectDir` and `file()`, and the members of `workflow`, `log` and `nextflow`, such as `workflow.projectDir` and `log.info`.
- Feature flags, such as `nextflow.enable.types`, and task properties, such as `task.attempt` and `task.cpus`.
- Members of the standard library types, such as `name` in `fasta.name`, if the block shows the type of the value.
- Processes and workflows from `include` statements, if you give the `modules` option.

Names in the `$name` and `${…}` parts of double-quoted strings link as they do in code. A code block with a title that ends in `.nf.test` is an nf-test file, and the adapter links nothing in it.

The adapter links an operator on a value that holds a channel. This is a channel factory, a call to a process or workflow, its `.out`, or a variable that holds one of these in every assignment. The adapter links a member of a type on these values:

- A variable that the block declares with a type, such as `fasta: Path` in a typed process.
- A `path` input of a legacy process.
- A variable that every assignment in the block sets to a value of one type, such as `file('ref.fa')`.
- The value that a linked member gives, so `fasta.name.toUpperCase()` links `name` and `toUpperCase`.

A name that the block assigns, or that is a closure parameter or a map key, does not link to a global name. In input and output declarations, `tuple`, `env` and `file` link to the qualifiers, not to the global functions.

A code block with a title that ends in `.config` is a config file. In a config file, the adapter links each setting, such as `docker.enabled`, and each setting in a scope block, such as `enabled` in `docker { enabled = true }`. It links the scope at the start of a block, such as `docker {`. A setting that the index does not list, such as `env.GREETING`, links its scope. The `params`, `process` and `profiles` scopes link to their sections of the Nextflow configuration page. Settings in a profile link as they do outside it.

The adapter also links the directives in the `process` scope, such as `memory` in `process.memory` or in `process { memory = '2 GB' }`, also inside `withName` and `withLabel`. For a config file with another title or none, add `nextflow="config"` to the fence line:

````md
```nextflow nextflow="config"
docker.enabled = true
```
````

<Options adapter="nextflow" />

`modules` gets the name in the module and the path after `from`. It returns the URL of the page, or an object with `href` and, if you want them, `kind`, `signature`, `summary` and `source`. It returns `undefined` for a name that must stay plain text. This site links nf-core modules to their pages on the nf-core site:

```js title="astro.config.mjs"
nextflow({
  modules: ({ name }) => ({
    href: `https://nf-co.re/modules/${name.toLowerCase()}`,
    kind: 'process',
    source: 'nf-core modules',
  }),
});
```

To link to the docs of an older Nextflow version, set `version` to the language server release for it:

```js title="astro.config.mjs"
nextflow({ version: '26.10.1' });
```

## API index adapter

The API index adapter links the names of any language or library that has an API index. An API index is a JSON file with each name and its docs link, and if you want, its signature, summary and type. The Nextflow language server makes one for each release. Give the adapter the code block languages and the index:

```js title="astro.config.mjs"
import codeblocks from 'starlight-codeblocks';
import { apiIndex } from 'starlight-codeblocks/adapters/api-index';
import { nextflow } from 'starlight-codeblocks/adapters/nextflow';
import { python } from 'starlight-codeblocks/adapters/python';

codeblocks({
  apiLinks: {
    adapters: [python(), nextflow(), apiIndex({ languages: ['tally'], index: 'https://tally.example/api-index.json' })],
  },
});
```

<Options adapter="apiIndex" />

An API index looks like this:

```json title="api-index.json"
{
  "apiIndex": 1,
  "source": "Tally reference",
  "base": "https://tally.example/docs/",
  "symbols": [
    {
      "name": "open",
      "kind": "function",
      "href": "io#open",
      "signature": "open(path: String) -> File",
      "summary": "Opens a file.",
      "type": "File"
    },
    { "name": "File", "kind": "type", "href": "file", "extends": ["Stream"] },
    { "name": "File.lines", "kind": "property", "href": "file#lines", "type": "List<String>" }
  ]
}
```

| Field | Description |
|---|---|
| `apiIndex` | The version of the format: `1`. |
| `source` | The name of the docs. The card shows it. |
| `base` | The URL that each `href` is relative to. |
| `symbols[].name` | The name. A member has its namespace or type before it, with a dot, such as `log.info` or `File.lines`. |
| `symbols[].kind` | What the name is, such as `function` or `property`. The card shows it when there is no signature. |
| `symbols[].href` | The docs link, relative to `base`. |
| `symbols[].signature` | Optional. The head of the card. |
| `symbols[].summary` | Optional. One sentence, in Markdown. |
| `symbols[].type` | Optional. The type of the value: the return type of a function, or the type of a property. |
| `symbols[].extends` | Optional, for a type. The types whose members the type also has. |
| `symbols[].context` | Optional. Where the name applies, such as `process` for a Nextflow directive. |

The adapter links:

- Each name in the index that the block does not assign.
- Each part of a dotted name that is in the index, such as `log` and `info` in `log.info`.
- The members of a value whose type it knows, through the `type` of each name and the types in `extends`. In `open('a').lines`, it links `lines` as `File.lines`.
- The members of a variable that the block declares with a type, such as `f: File`, or that each assignment sets to one type.

A name with a `context` applies only in one part of the code, and only an adapter for the language knows where that part is. The API index adapter does not link these names. The Nextflow adapter reads the contexts of the Nextflow index.

## Limitations

- The Python adapter does not follow assignments. After `p = Path("run.json")`, the name `p.read_text` stays plain text.
- The Python adapter does not link built-in names, such as `print` and `len`.
- A name that the block binds again, for example with `json = {}` or as a function parameter, does not link anywhere in the block.
- The Nextflow adapter does not link operators after the `|` operator.
- The Nextflow adapter does not know the type of a closure parameter, such as `it` or `bam` in `{ bam -> bam.name }`. The members of a closure parameter stay plain text.
- A qualifier, a standard library type member or a global name links to its section or page, not to its own heading. The anchors of these headings come from their signatures, so they change when a signature changes.
- In a config file, names in values, such as `params` after `=`, stay plain text. Only task properties, such as `task.attempt`, link there.
- The files in `node_modules/.cache/starlight-codeblocks/` do not expire, also the index of the latest language server release. Delete the folder to fetch the indexes again.
- The API index adapter knows only the comments and strings of a language. It does not link names that have a `context`.
- A link cannot span two lines.
- Names on the line that a `[!link]` directive targets do not link, so that a link is never inside another link.
