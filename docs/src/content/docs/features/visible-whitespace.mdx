A code block usually renders whitespace as empty space. That is fine for most languages, but some depend on the exact character. Make needs a tab at the start of a recipe, and Python needs consistent indentation. The `whitespace` attribute shows spaces and tabs as glyphs, so readers see which character is there.

export const basic = `
\`\`\`make title="Makefile" whitespace
build:
\tcargo build --release

test:
    cargo test  # Recipes must start with a tab
\`\`\`
`;

<Example code={basic} />

The first recipe starts with an arrow, for the tab that Make needs. The second starts with four dots, for the four spaces that Make rejects. Copying the block gives the real characters, not the glyphs.

## Syntax

| Syntax | Where | Effect |
|---|---|---|
| `whitespace` | Fence line | Shows the leading whitespace of every line |
| `whitespace="all"` | Fence line | Shows every space and tab in the block |

## Behaviour

- A space renders as a middle dot. A tab renders as an arrow at the start of the tab. The tab keeps its width up to the next tab stop, which the CSS `tab-size` property sets.
- By default, the plugin shows only the leading whitespace of each line, where indentation usually matters. `whitespace="all"` shows every space and tab, including the ones between words.
- The glyphs are drawn with CSS on top of the real character. A manual copy or the copy button gives the actual spaces and tabs.
- Screen readers do not hear the glyphs. They read the same code as a block without the attribute.
- Visible whitespace needs no JavaScript in the browser.

## Options

Visible whitespace has no options. Turn it off for the whole site with `whitespace: false`:

```js title="astro.config.mjs"
codeblocks({
  whitespace: false,
});
```

## Examples

`whitespace="all"` shows every space, which is useful when trailing whitespace is part of what you are explaining:

export const trailing = `
\`\`\`text title="diff.patch" whitespace="all"
-  const width = 10; 
+  const width = 12;
\`\`\`
`;

<Example code={trailing} />

Leading whitespace alone is usually enough to show an indentation error:

export const python = `
\`\`\`py title="script.py" whitespace
def greet(name):
    print(f"Hello, {name}")
   return None  # Indented with 3 spaces, not 4
\`\`\`
`;

## Limitations

- The glyphs add visual noise on a block with a lot of whitespace. Use `whitespace="all"` only where the extra detail matters, and leave the default, leading-only view for everything else.
- Expressive Code turns every tab into spaces before this feature can see it. `codeblocks()` sets `tabWidth: 0` for you unless you already chose your own value. A tab then reaches the plugin unchanged, and a Makefile block copies its real tab rather than spaces. Set `expressiveCode.tabWidth` in the Starlight config, or `tabWidth` in `ec.config.mjs`, for Expressive Code's normal tab-to-space expansion instead.
