A walkthrough of a file often puts the whole block first, then explains it in paragraphs below. Readers scroll back up to find each line that a paragraph names. Scrollycoding keeps the block next to the prose. As each step scrolls past the middle of the window, the block focuses the lines of that step.

Scroll down the page. The block stays below the site header, and each step that reaches the middle of the window changes the focus. On a narrow screen, each step has its own copy of the block, focused for that step.

## Syntax

| Syntax | Where | Example |
|---|---|---|
| `<Scrollycoding>` ... `</Scrollycoding>` | Around one code block and its steps, in an MDX file | `<Scrollycoding>` |
| `<Step>` ... `</Step>` | After the code block, one for each step | `<Step focus="6-8">Text</Step>` |
| `focus="<range>"` | On `<Step>` | `focus="6-8"` |
| `mark="<range>"` | On `<Step>` | `mark="4"` |

Import both components at the top of the MDX file:

```mdx
import { Scrollycoding, Step } from 'starlight-codeblocks/components';
```

Put one code block first, then the steps. Leave an empty line after `<Scrollycoding>` and before `</Scrollycoding>`. `focus` and `mark` take a [range](/starlight-codeblocks/features/comment-notation/#line-numbers) without braces, such as `4` or `1, 6-8`. A step can contain any Markdown, such as links, inline code or several paragraphs.

## Behaviour

- On a wide screen, the steps are a column on the left, and the block is on the right. The block stays below the site header while the steps scroll with the page.
- The step that crosses the middle of the window is the active step. It shows at full opacity, and the other steps fade.
- When the active step changes, the block changes its focused and marked lines, with the 250 ms transition of [focus](/starlight-codeblocks/features/focus/).
- The block stays blurred when the pointer is over it, because the pointer often rests there while the reader scrolls. Move keyboard focus into the block to make every line sharp.
- On a narrow screen, each step shows its own copy of the block below its text. The two columns need a content width of 600 px or more.
- When the reader's system asks for reduced motion, the focus and the fade change without a transition.
- The copy button copies the whole block, in every step.
- Without JavaScript, the page shows the narrow layout at every width.

## Options

Scrollycoding has no options. To turn the feature off for the whole site, set `scrollycoding` to `false`:

```js title="astro.config.mjs"
codeblocks({
  scrollycoding: false,
});
```

With `scrollycoding: false`, `<Scrollycoding>` shows the narrow layout at every width, with no script.

## Examples

A step can mark a line as well as focus a range. Here, the second step keeps the whole function in focus and marks the line that changes the total:

export const marks = `
<Scrollycoding>

\`\`\`py title="cart.py"
def total(items, discount=0):
    subtotal = sum(item.price for item in items)
    return subtotal * (1 - discount)
\`\`\`

<Step focus="1">The function takes the items and an optional discount, from 0 to 1.</Step>
<Step focus="1-3" mark="3">The last line applies the discount to the subtotal.</Step>

</Scrollycoding>
`;

## Limitations

- `<Scrollycoding>` works in MDX files only, because Markdown files cannot contain components.
- A `<Scrollycoding>` holds one code block. To show code that changes between steps, use [token transitions](/starlight-codeblocks/features/token-transitions/).
- The narrow layout repeats the block for each step, so a long block with many steps makes a long page.
- The component replaces the focus of the block. A `focus` attribute on the fence line has no effect.
