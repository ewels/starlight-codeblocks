Starlight shows inline code in the prose in one colour, with no syntax highlighting. A short expression such as a function call is then harder to read than the same code in a block. A `{:lang}` suffix after the closing backtick gives the inline code the syntax colours of that language.

export const basic = `
Call \`await fetch(url)\`{:js} and check \`res.ok\`{:js} before you read the body.
`;

<Example code={basic}>

Call `await fetch(url)`\{:js} and check `res.ok`\{:js} before you read the body.

</Example>

The two pieces of inline code get the colours and the background of the site's code blocks. The plugin removes the suffix, so readers see only the code.

## Syntax

| Syntax | Where | Example |
|---|---|---|
| `` `<code>`{:<lang>} `` | Prose, directly after the closing backtick | `` `res.ok`{:js} `` |

`<lang>` is a language name or alias that Expressive Code knows, the same as on a fence line: `js`, `py`, `sh`, `css` and others. Languages that the site adds in the `shiki.langs` option of Expressive Code work too. The suffix must follow the backtick with no space between them. The syntax is the same as in rehype-pretty-code.

<Aside type="caution">
In `.mdx` files, write a backslash before the suffix: `` `res.ok`\{:js} ``. MDX reads `{:js}` as a JavaScript expression, and the build fails without the backslash. In `.md` files, write the suffix without a backslash.
</Aside>

## Behaviour

- The inline code uses the site's Expressive Code themes: the background and the token colours of the dark theme and the light theme.
- The colours change with Starlight's theme menu, the same as the code blocks.
- The colours have the same contrast correction as the code blocks.
- The plugin removes the suffix from the page.
- Inline code without a suffix does not change.
- If Expressive Code does not know the language, the code shows as normal inline code and the build logs a warning with the file name. The plugin removes the suffix.
- The highlighting happens at build time, so it works without JavaScript. Pages with no code blocks get the colours too.
- The highlighted code is a normal `code` element. Screen readers and the copied text get the same characters as before.

## Options

Inline code highlighting has no options. Turn the feature off for the whole site with `inlineHighlighting: false`:

```js title="astro.config.mjs"
codeblocks({
  inlineHighlighting: false,
});
```

With `inlineHighlighting: false`, the suffix stays in the prose as text.

## Examples

A shell command in a sentence:

export const shell = `
Install the package with \`pnpm add starlight-codeblocks\`{:sh}, then restart the dev server.
`;

<Example code={shell}>

Install the package with `pnpm add starlight-codeblocks`\{:sh}, then restart the dev server.

</Example>

A CSS declaration and a Python expression in a list:

export const list = `
- Hide the element with \`display: none\`{:css}.
- Round the value with \`round(total / count, 2)\`{:py}.
`;

<Example code={list}>

- Hide the element with `display: none`\{:css}.
- Round the value with `round(total / count, 2)`\{:py}.

</Example>

## Limitations

- Inline code cannot use the attributes or directives of code blocks, such as focus or line states.
- The code must be on one line. Expressive Code highlights it as a code block of one line. An unclosed string colours the rest of the code as a string.
