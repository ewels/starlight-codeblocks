A code block in Starlight shows code, but readers must copy it to a terminal to see what it does. The `runnable` attribute adds a **Run** button to the title bar. The button runs the code in the browser and shows the output under the block.

export const basic = `
\`\`\`py runnable
from statistics import mean, stdev

reads = [1520, 1610, 1480, 1575]
print(f"mean {mean(reads):.0f}, sd {stdev(reads):.1f}")
\`\`\`
`;

<Example code={basic} hiddenAttributes="apiLinks=false" />

Select **Run**. The first time, the browser downloads Python (Pyodide, a build of Python for the browser), which takes a few seconds. The output panel shows "Loading the Python runtime…" until it is ready, then the output of the code.

## Syntax

| Syntax | Where | Example |
|---|---|---|
| `runnable` | Fence line | ` ```py runnable ` |

The language of the block chooses the runtime. The plugin has a runtime for Python, and a site can add runtimes for other languages in the configuration. A language name or its alias works: `py` and `python` both use the Python runtime.

## Behaviour

- The runtime loads only when a reader selects **Run** for the first time. A page with runnable blocks loads a script of less than 1 kB, and no runtime.
- After the first run, the button reads **Run again**. Each run replaces the output of the run before it.
- The code that runs is the copied text of the block. Directives are removed, and hidden lines are kept. The values that readers type into [fill-in placeholders](/starlight-codeblocks/features/fill-in-placeholders/) are part of it too.
- The output panel has the label "Output". Standard output shows in green. Standard error shows in red, with a bar at its start, so the colour is not the only difference.
- A run stops after 10 seconds, with a message in the panel. The download of the runtime does not count towards this time.
- The Python runtime runs in a web worker, so the page stays responsive while code runs. Each run starts with no names from earlier runs.
- The output panel is a polite live region. Screen readers announce the loading message and the output when they change.
- The button keeps the keyboard focus during a run, so readers can run the code again with <kbd>Enter</kbd> or <kbd>Space</kbd>.
- The Run button does not print. Without JavaScript, the Run button is hidden.

## Options

<Options />

A runtime module is a package path, or a path from the project root. This site adds a runtime for JavaScript, and gives runs 5 seconds:

```js title="astro.config.mjs"
codeblocks({
  runnable: {
    runtimes: { javascript: './src/runtimes/javascript.ts' },
    timeout: 5000,
  },
});
```

The guide to [adding a runtime](/starlight-codeblocks/extend/add-a-runtime/) shows this runtime in full.

## Examples

A JavaScript example runs with the runtime from the configuration above. `console.log()` goes to standard output and `console.error()` to standard error:

export const js = `
\`\`\`js runnable
const sizes = [3, 1, 4, 1, 5];
const total = sizes.reduce((sum, size) => sum + size, 0);
console.log('Total:', total);
console.error('Sizes of 1 are deprecated.');
\`\`\`
`;

An error in Python shows the traceback, from the line of the example that failed:

counts = {"passed": 3, "failed": 0}

\`\`\`js runnable
let ready = false;

\`\`\`
`;

## Limitations

- The code must be complete to run. Put the imports and set-up in [hidden lines](/starlight-codeblocks/features/hidden-lines/) if they distract from the example.
- The Python runtime has no standard input, so `input()` fails.
- Python packages outside the standard library must be part of Pyodide. The runtime installs them from the `import` lines of the example.
- The Python runtime loads Pyodide from the jsDelivr CDN, and runs its worker from a `blob:` URL. A Content Security Policy must allow both.
- To stop a Python run, the runtime ends its worker. The next run downloads the runtime again, from the browser cache if the browser kept it.
