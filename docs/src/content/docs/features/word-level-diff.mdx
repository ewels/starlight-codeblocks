Expressive Code tints the added and removed lines of a `diff` block. Word-level diff also highlights the words that changed inside each pair of lines, so readers can find a one-word edit in a long line.

export const basic = `
\`\`\`diff lang="js"
-const timeout = 5000;
+const timeout = options.timeout ?? 5000;
const client = createClient({
-  retries: 3,
+  retries: options.retries,
});
\`\`\`
`;

<Example code={basic} />

The new `timeout` line adds `options.timeout ??`, and `3` becomes `options.retries`. The plugin pairs each removed line with the added line below it, compares them word by word, and gives the changed words a stronger tint. The rest of the line keeps the plain diff tint, and the syntax colours stay in place.

## Syntax

| Syntax | Where | Example |
|---|---|---|
| A `diff` block | Fence line | `diff lang="js"` |
| `ins={range}`, `del={range}` | Fence line | `ins={2} del={1}` |
| `[!code ++]`, `[!code --]` | Comment | `retries: 3, // [!code --]` |
| `wordDiff=false` | Fence line | Turns the feature off for one block |

Word-level diff applies to every removed line that has an added line below it, from any of these sources. You do not turn it on.

## Behaviour

- The plugin pairs a run of removed lines with the run of added lines below it, one by one.
- Each pair is compared token by token: words, runs of whitespace and single punctuation characters.
- The changed tokens get a stronger tint. Whitespace between two changed tokens is part of the highlight, so a run of changed words tints as one block.
- Added words are also underlined, and removed words have a line through them, so the change does not rely on colour.
- If a pair is less than 40% similar, it is too different to compare. The plugin leaves the whole-line tints in place and adds no word highlight.
- The underlying syntax highlighting stays visible under the tint.
- Word-level diff needs no JavaScript in the browser.

## Options

<Options />

Some codebases rewrite lines often enough that the word-level highlight adds noise more often than it helps. Raise the threshold to show it only for close edits:

```js title="astro.config.mjs"
codeblocks({
  wordDiff: { minSimilarity: 0.7 },
});
```

## Examples

The `ins` and `del` attributes give the same result as a `diff` block, without changing the language of the block:

export const attributes = `
\`\`\`js title="server.js" ins={2} del={1}
const port = 3000;
const port = Number(process.env.PORT ?? 3000);
\`\`\`
`;

<Example code={attributes} />

`[!code --]` and `[!code ++]` move with their line when you edit the code:

export const directives = `
\`\`\`py title="config.py"
TIMEOUT = 30  # [!code --]
TIMEOUT = 60  # [!code ++]
\`\`\`
`;

<Example code={directives} />

A rewritten line is too different to compare, so it keeps a plain diff tint:

export const different = `
\`\`\`diff lang="js"
-const total = a + b;
+export function computeGrandTotal(items) {
+  return items.reduce((sum, item) => sum + item.price, 0);
+}
\`\`\`
`;

## Limitations

- Pairing is by position. The first removed line pairs with the first added line, the second with the second, and each later pair the same way. A block that adds or removes a different number of lines can pair the wrong lines.
- The comparison works on the visible text of the line. It does not parse the language, so it cannot tell that `total` and `sum` are the same value with a new name.
- The plugin does not compare a long pair of lines, such as two lines of minified code. If the number of tokens in the removed line multiplied by the number in the added line is more than 1,000,000, the whole-line tints stay.
