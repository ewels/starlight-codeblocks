An example often shows only part of a file. Authors then write a comment such as `// ...` where code is left out, and readers can mistake it for code. Skipped code puts a marker in its place, which looks different from the code and is not part of the copied text. Write the `[!code skip]` directive, with optional text. A site can also read its `// ...` comments as markers, with [aliases](#aliases).

export const basic = `
\`\`\`js title="routes.js"
const app = express();

app.get('/users', async (req, res) => {
  // [!code skip] Not shown: Read the users from the database
});

app.post('/users', async (req, res) => {
  const user = await db.users.create(req.body);
  res.status(201).json(user);
});
// [!code skip]
\`\`\`
`;

<Example code={basic} />

The first marker replaces the body of the `get` handler and shows the text after the directive. The second marker shows that the file goes on after the last line. Copying the block gives the code without the markers.

## Syntax

| Syntax | Where |
|---|---|
| `[!code skip]` | Comment on its own line, or at the end of a line |
| `[!code skip] text` | Comment on its own line, or at the end of a line |

Put the directive on its own line where the code is left out. The marker takes the place of that line, with the same indentation. At the end of a line, the marker goes above that line. Without text, the marker reads "Code not shown". The text can hold inline code, links and bold text.

:::tip
Does your site already use `// ...` comments for code that is left out? Set [aliases](#aliases) to show them as markers, without rewriting them as directives. Aliases are off by default, because they change the line ranges of existing blocks.
:::

## Aliases

Many pages already use `// ...` for code that they leave out. By default, these comments stay in the code as written. To read them as markers, set `skippedCode.aliases`:

```js title="astro.config.mjs"
codeblocks({
  skippedCode: { aliases: ['...'] },
});
```

A line is then the same as `[!code skip]` if it holds one of these, and nothing else:

- A comment with only `...` in it, in the comment syntax of the language: `// ...`, `# ...`, `/* ... */` or `<!-- ... -->`.
- `...` with no comment, in JSON. JSON has no comments, so the directive cannot go in a JSON block.

Add more aliases to the list, such as `'…'`. An alias takes no text: for a marker with text, write `[!code skip] text`. This site sets `['...']`, so this JSON block shows two markers:

export const json = `
\`\`\`json title="package.json"
{
  "name": "my-site",
  "scripts": {
    "dev": "astro dev",
    ...
  },
  ...
}
\`\`\`
`;

<Example code={json} layout="tabs" />

In Python, `...` is code, and in YAML it ends a document, so a `...` with no comment stays in these blocks.

:::caution
Aliases change existing pages. Check the pages that use `// ...` after you set them:

- The `// ...` lines leave the code, so line ranges count different lines. In a block with `// ...` on line 2, `{4}` marks the line that was line 5. This applies to every range attribute, such as `ins={4}` and `focus={4}`.
- The `// ...` lines also leave the copied code.
- A [code walkthrough](/starlight-codeblocks/features/code-walkthrough/) or [scrollycoding](/starlight-codeblocks/features/scrollycoding/) step with a marker changes without the animation.
:::

To keep `// ...` as code in one block, add text to the comment, such as `// ... and so on`. A comment with more than an alias in it stays in the code. A language with `[]` in `notation.comments` reads no directives and no aliases.

## Examples

### Skip code without text

Without text, the marker reads "Code not shown". Use it when the code around the marker tells readers what is left out:

export const noText = `
\`\`\`ts title="cache.ts"
export class Cache<T> {
  private entries = new Map<string, T>();

  // [!code skip]

  get(key: string): T | undefined {
    return this.entries.get(key);
  }
  // [!code skip]
}
\`\`\`
`;

<Example code={noText} layout="tabs" />

### Skip the start of a file

A marker on the first line shows that the example starts in the middle of a file:

export const start = `
\`\`\`py title="report.py"
# [!code skip] Not shown: Imports and settings
def summarise(rows):
    totals = {}
    for row in rows:
        totals[row["status"]] = totals.get(row["status"], 0) + 1
    return totals
\`\`\`
`;

<Example code={start} layout="tabs" hiddenAttributes="apiLinks=false" />

### Skip a section of a configuration file

YAML uses `#` comments. For JSON, use `jsonc`, because JSON has no comments:

export const config = `
\`\`\`yaml title="docker-compose.yml"
services:
  web:
    image: nginx:1.27
    ports:
      - "8080:80"
  # [!code skip] Not shown: The database and cache services
volumes:
  data:
\`\`\`
`;

## Behaviour

- The marker:
  - A dotted rule across the block, with the text in a badge at the indentation of the directive line.
  - The marker is not a button. Readers cannot open it, because the code is not in the block.
- Line numbers:
  - The marker has no line number, and the line numbers do not jump over it.
- Copy and selection:
  - The copy button copies the code without the markers. A manual selection never includes the text of a marker.
- Screen readers:
  - Screen readers read the text of the marker in its place among the lines.
- Print:
  - Markers print.

## Options

<Options />

Turn the feature off for the whole site with `skippedCode: false`. The plugin then does not know the `[!code skip]` directive. It leaves the directive in the code as written, and logs a build warning.

## Limitations

- The directive needs a comment. JSON has no comments and can use only the `...` alias, so its markers have no text.
- A code walkthrough or scrollycoding step with a marker changes without the animation. The animation does not have the height of the marker.
- Line numbers do not jump over the skipped code. To start a block at a later number, use the `startLineNumber` attribute of Expressive Code.
- The copied code is incomplete, so it can fail to run. Do not use skipped code in a block with a **Run code** or playground button.
