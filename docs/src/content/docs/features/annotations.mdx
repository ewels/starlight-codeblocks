A comment in a code block explains a line. But it takes space in the code, and readers copy it with the code. An annotation moves the explanation out of the code. The line gets a small numbered marker, and the note opens in a popover when a reader selects the marker.

export const basic = `
\`\`\`yaml title=".github/workflows/test.yml"
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python: ["3.12", "3.13"]  # [!annotate] One job per version, run in parallel.
    steps:
      - uses: actions/checkout@v7
      - uses: astral-sh/setup-uv@v6  # [!annotate] Installs \`uv\` and caches its downloads between runs.
      - run: uv run pytest
\`\`\`
`;

Each `[!annotate]` comment is gone from the output. A numbered marker is in its place, after the code on the line. Hover over a marker to see its note, or select the marker to keep the note open. Press Escape or select anywhere else to close the notes.

## Syntax

| Syntax | Where | Example |
|---|---|---|
| `[!annotate] note` | Comment at the end of a line | `run: uv run pytest  # [!annotate] Runs the tests.` |
| `annotations="side"` | Fence line | `annotations="side"` |

The directive goes at the end of the line it explains. The note is the rest of the comment. It can hold inline code, links and bold text. `annotations="side"` shows the notes in a column beside the code instead, as the [side-by-side annotations](/starlight-codeblocks/features/side-by-side-annotations/) page explains.

## Behaviour

- Markers are numbered from 1 in each block, in line order.
- Hovering over a marker with a mouse shows its note. The note hides when the pointer leaves the marker and the note. So the pointer can move into the note, for example to select a link. Selecting the marker, or the number at the start of the note, keeps the note open. Selecting it again closes the note.
- Selecting a marker opens its note out of the marker. The note starts with the same number, on top of the marker. The box goes to the right, over the empty space after the line. A long note wraps onto more lines, up to the popover width (340 px by default).
- If the box does not fit there, the note opens under the marker instead. It is centred and as wide as the popover width, with the number at its start. The box does not fit when it would cover code on its line or the lines next to it. It also does not fit when it would go past the right edge of the block or the window. On a phone, most notes open this way. The note moves between the two places when the window changes size or the page scrolls.
- If there is no room under the marker, the note opens above it. Several notes can be open at once, and hovering over a marker still shows its note while others are open.
- The number in the note is hidden from screen readers, because the marker already has the label.
- Escape, or a selection outside the markers and the notes, closes every open note. Without JavaScript, a second selection of the marker closes its note.
- The copy button leaves the markers and the notes out. A manual selection leaves the markers out.
- Each marker is a button with the label "Annotation N", where N is its number. Screen readers read the note directly after its marker.
- When the page prints, each marker prints as its number, and the notes print as a numbered list under the block.
- The browser's `popover` attribute opens and closes the notes, so they work without JavaScript. Without JavaScript, the note always opens under the marker. In browsers without CSS anchor positioning, it opens where the browser puts it by default.
- The note fades in and out in 160 ms. With reduced motion, it opens and closes at once.
- The pointer is a hand on the marker and on the number of an open note, which covers the marker.
- When the pointer is on a marker, or the marker has keyboard focus or an open note, it changes colour. On hover, the colour fades in on the timing of the note: it waits 80 ms, then fades for 160 ms. With reduced motion, it changes at once. The colour is the marker colour moved towards the code text: lighter in dark themes and darker in light themes.

## Options

Annotations have no options. Turn the feature off for the whole site with `annotations: false`:

```js title="astro.config.mjs"
codeblocks({
  annotations: false,
});
```

With `annotations: false`, the plugin does not know the `[!annotate]` directive. It leaves the comment in the code as written, and logs a build warning. Side-by-side annotations are off too.

## Examples

A note can hold a link, for a line that needs more explanation than a sentence:

export const link = `
\`\`\`ts title="retry.ts"
export async function retry<T>(task: () => Promise<T>, attempts = 3): Promise<T> {
  for (let i = 1; ; i++) {
    try {
      return await task();
    } catch (error) {
      if (i >= attempts) throw error; // [!annotate] Gives up and passes on the last error. See [Error handling](https://example.com/errors).
      await new Promise((done) => setTimeout(done, 2 ** i * 100)); // [!annotate] Waits 200 ms, then 400 ms: an exponential backoff.
    }
  }
}
\`\`\`
`;

## Limitations

- The note is part of the source line. Long notes make long lines in the Markdown file.
- An annotation applies to one line. For a note about a range of lines, put it on the first line of the range.
- Readers see a note only when they open it. If readers need every note to follow the code, use [footnotes](/starlight-codeblocks/features/footnotes/) or [side-by-side annotations](/starlight-codeblocks/features/side-by-side-annotations/).
